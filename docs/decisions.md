## 2026-11-14 — Структура проекта

**Решили:** плоская структура по типам файлов:
public/ (docroot), src/ (логика), templates/ (вид), data/ (данные),
docs/ (документация), README.md, .gitignore.

**Почему:** новичку и одному разработчику — понятно и быстро. Это упрощённый
MVC без ООП: слой данных = функции в src/, вид = templates/, контроллер =
обработчик маршрута.

**Отвергли:**
- feature-based (posts/, auth/) — избыточно для MVP.
- настоящий MVC с Models/Controllers/ — рано без ООП.
- всё в одном index.php — неподдерживаемо.

**Когда пересмотрим:** когда файлов станет >50 или появится реальная боль.
Не проектируем на вырост, рефакторим когда боль реальна.

## 2026-11-14 — Единственная точка входа

**Решили:** все запросы идут в public/index.php. Docroot = public/.
Никаких прямых обращений к .php-файлам из веба, кроме index.php и статики.

**Почему:** безопасность (код и данные вне docroot), единый роутинг,
легко добавить общую логику (сессии, ошибки, layout) в одном месте.

## 2026-11-14 — REQUEST_URI vs parse_url

**Решили:** роутер получает путь через
`parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH)`.

**Почему:**
- `$_SERVER['REQUEST_URI']` — сырая строка от браузера, включает query string.
  Пример: для `/about?ref=menu` там `/about?ref=menu`.
- `parse_url(..., PHP_URL_PATH)` отрезает всё после `?`, оставляет только путь:
  `/about`.
- Сравнивать с таблицей маршрутов надо чистый путь, иначе `/about?ref=menu`
  не совпадёт с ключом `/about` и отдаст 404 на существующую страницу.

**Сопутствующее:** query string PHP сам разбирает в `$_GET` до запуска
index.php. Не путать: query string (что) → `$_GET` (куда). HTTP-метод GET/POST —
отдельная шкала (что за запрос). POST-тело → `$_POST`, не `$_GET`.

## 2026-11-14 — Слеш в конце URL

**Решили:** все маршруты без слеша в конце, кроме корня `/`.
В роутере нормализуем: `/about/` → `/about`.

**Почему:** `/about` и `/about/` — разные строки, `parse_url` их не нормализует.
Без политики получим дубли URL и непредсказуемый 404. Один канонический URL
на страницу — это и SEO, и меньше багов.

## 2026-11-14 — Категории постов

**Решили:** 4 стартовые категории. Slug латиницей (a-z, 0-9, -), название по-русски.

- `devlog` — Дневник разработки
- `mechanics` — Механики
- `world` — Мир
- `code` — Код

**Почему:** slug идёт в URL и имена файлов — только латиница. Название —
для отображения пользователю.

---

## 2026-11-14 — Формат постов

**Решили:** на MVP — plain text. Markdown — отдельным milestone позже.

**Почему:** plain text не требует парсера и не создаёт вектора XSS через
Markdown-рендеринг. Сначала данные и поток, потом косметика.
Когда добавим Markdown — добавим и санитайзер, осознанно.

## 2026-11-14 — Хранилище данных (прогрессия)

**Решили:** прогрессия PHP-массивы → JSON → SQLite.
Цель — понять, какую проблему решает каждый слой. Таймбокс: не застревать
на этапе >2 дней.

**Почему:** на старте — простота, чтобы не утонуть в SQL/PDO. Финал —
SQLite (файл, без сервера) + PDO, когда почувствуем боль: выборки, сортировка,
пагинация, связи категорий.

**Правило слоя данных:** доступ к данным — только через функции
(get_all_posts(), get_post_by_slug() и т.п.). Шаблоны НЕ знают, откуда данные
(JSON/SQLite). При смене хранилища шаблоны не меняются.

## 2026-11-14 — Админка: один админ

**Решили:** один админ, логин + пароль. Пароль хранится только как хеш
(`password_hash`), никогда в открытом виде. Пароль/секреты — в `.env`,
не в репозитории. `.env` в `.gitignore`, в репо — `.env.example`.

**Почему:** минимально достаточно для MVP. Хеширование — обязательный
минимум, не обсуждается. Утечка пароля в git — классическая катастрофа.

---

## 2026-11-14 — .gitignore

**Решили:** игнорируем `.env`, `vendor/`, `node_modules/`, логи, `*.sqlite`,
локальные ddev-каталоги (`.homeadditions/`, `db_snapshots/`, `.router` и т.п.),
`.vscode/`, `.idea/`.

**Что коммитим:** `.ddev/config.yaml` — без него проект не поднимется у
другого человека. `composer.json`/`composer.lock` (когда появятся).
`.env.example` — с пустыми значениями.

**Почему:** репозиторий = исходники + конфиги, без которых проект не
собирается. Не репозиторий = сгенерированное, локальное, секретное.

**.vscode/ — осознанный выбор:** настройки личные, не командные. Для соло — ок.
